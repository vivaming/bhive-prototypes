# BIHIVE QA

`pnpm install --frozen-lockfile` restores exact build/test dependencies. `pnpm qa:all` runs offline: each asset locks its checked-in highest-resolution WebP as the canonical rebuild master, and the pipeline verifies that master's SHA-256 before deterministically rebuilding and hashing lower-resolution variants. The original Commons page, author, license, source-file SHA-256 and evidence record remain available as provenance; the QA report explicitly says the original JPEG is not rebuilt. This avoids network-dependent CI and keeps the repository increase to the regenerated lower variants instead of adding all 72 MB of original JPEGs. The pipeline also verifies licensing/evidence hashes, runs static checks, creates two reproducible builds, and runs the Chromium browser suite. The structured result is written to `work/qa-report.json`; the Playwright JSON report and failure artifacts are also kept under `work/` and `test-results/`.

`pnpm qa:browser` starts a minimal static server on loopback and executes Chromium tests at desktop and mobile viewports, including reduced-motion, layout-boundary, image-decode, keyboard and navigation checks. Set `BIHIVE_QA_URL` only when intentionally testing a separately permitted browser target; this override disables the local server. GitHub Actions installs Chromium and runs the same `pnpm qa:all` pipeline on pushes and pull requests, then uploads the structured report and browser artifacts. The QA report only marks the browser checks and overall status PASS when Playwright actually completes successfully. Screenshot review is not claimed by the automated tests.

Photo coverage is intentionally conservative. Each admitted Commons image has a saved description-page record, license, author, date, file hash and a written story-specific relevance explanation. Other stories use their existing original illustration or text card and a recorded `NO_APPROVED_PHOTO` reason.
